# `static/blog/js/` — клиентский JS платформы

Раньше почти весь фронтенд-JS жил инлайном в `base.html` (~2430 строк в одном
`<script>`). Он вынесен сюда и разбит по темам (Фаза 4 рефакторинга). `base.html`
теперь — каркас разметки + маленький конфиг `window.VC_URLS` + подключения этих файлов.

## Как это работает

- Файлы грузятся **обычными `<script src>`** (не ES-модули), поэтому все функции
  остаются в **глобальном scope** — как и было в едином `<script>`. `initPageContent`
  и soft-navigation зовут их через `window[fnName]`.
- **Порядок подключения важен** (задан в `base.html`): модуль может вызывать функции
  предыдущих. В конце каждого модуля — самовызовы `initXxx(document)`, инициализирующие
  текущую страницу; поэтому функция должна быть определена в том же или раньше
  загруженном файле.
- Статические `.js` **не рендерят Django-теги**. Серверные URL приходят через
  `window.VC_URLS` (инлайн-конфиг в `base.html` с `{% url %}`). Нужен новый URL в JS —
  добавь его в `VC_URLS`, а не в `.js`.

Общая оболочка подключает JS/CSS через `{% versioned_static %}` (`custom_tags.py`).
При DEBUG=True адрес содержит хеш исходного файла: старый кэш браузера не продолжает
выполнять прежний поиск после обновления. Хеш кэшируется до изменения метаданных
файла. При DEBUG=False сохраняются штатные URL с хешем из staticfiles manifest.
Полный кэш данных таблицы и предпочтение «Подгрузить всё» от этого не очищаются.

## Что в каком файле

У существующих `form[data-disable-on-submit]` необязательный `data-submitting-text`
меняет текст кнопки при отправке, ставит aria-busy и показывает `[data-submit-status]`.
Это использует подтверждение большого легаси-импорта; остальные формы сохраняют
прежнюю блокировку кнопки. Отменённый submit индикатор не включает.

`misc.js` → `initPositionHandouts(root)` связывает `[data-handout-kind]` в таблице
позиции. URL POST приходит в `data-handout-url` из шаблона. Обед синхронизируется по
человеку/смене, жетон — по человеку/мероприятию во всех строках. Во время запроса
связанные галочки временно блокируются; при ошибке состояние восстанавливается,
сообщение появляется рядом с полем. После ответа галочки снова доступны.
Инициализация идемпотентна и включена в `initPageContent` для мягкой навигации.

`qr-scanner.js` — `initQrScanner(root)` для `[data-qr-scanner]`: камера, фото,
существующая модалка участника, POST сканирования/входа/выхода и освобождение камеры.
В карточке вход/выход/обед и значок — чекбоксы. Все отметки можно ставить и снимать,
включая сохранённые при прошлом сканировании; исходное состояние сравнивается с
выбором, пакет передаёт `checked: true/false`. Выход автоматически выбирает вход,
снятие входа снимает выход. До закрытия изменения остаются черновиком:
`qrCommit` атомарно сохраняет пакет с серверным временем сканирования. Общий
`closeModal` отправляет отменяемое `modal:before-close`; QR ждёт сохранения, после
успеха закрывает окно принудительно, при ошибке оставляет выбор. `modal:closed`
очищает черновик и в режиме камеры автоматически продолжает сканирование тем же
потоком. Карточка приостанавливает обработку кадров; один оставленный в кадре QR
не открывается повторно, пока не появился другой код или кадр без QR.
Явный Stop и уход со страницы освобождают поток. Режим камеры сохраняется в
sessionStorage отдельно от черновика, по оператору.
Переход в профиль сохраняет контекст и выбор в sessionStorage по оператору; Back
восстанавливает окно, BFCache не заменяет живую карточку параллельным запросом.
Закрытие ждёт окончания обновления/восстановления, чтобы ответ не потерял отметки.
`[data-qr-enroll]` записывает на смену и предлагает вход в том же черновике, сохраняя
другие выборы. При ошибке восстанавливаются исходные блокировки полей.
Декодер `vendor/jsQR.js` 1.4.0 загружается лениво, только при использовании сканера;
изображения камеры/файла обрабатываются локально. URL берутся из `window.VC_URLS`.

## Как добавлять

`tables.js::initTableFilter` — общий поиск по всем словам из `data-search`, в любом
порядке, без регистра, ё/е, @ и лишних пробелов; debounce 200 мс. При отсутствии
совпадений добавляет строку со статусом. Необязательный `[data-table-role-filter="#id"]`
фильтрует по `data-role`; существующий `data-table-hide-passed` работает совместно.
При изменении строк общий `table:rowschanged` повторяет актуальный поиск.

`initInfiniteScroll` поддерживает `?all=1` (полный `<tbody data-rows>` без следующей
страницы). Поиск/фильтр ролей автоматически запрашивает полный список; также есть
«Подгрузить всё». Параллельная загрузка страницы отменяется, устаревшие ответы не
добавляются. Загрузка сохраняет сортировку и скрытые колонки, ошибки можно повторить.
В localStorage хранится только предпочтение полной загрузки по URL/аккаунту из
`data-table-cache-owner`; HTML хранится в приватном HTTP-кэше браузера. В списке
пользователей `services/user_table.py` формирует ETag по отображаемым данным, активным
ролям и московской дате; при повторном заходе сервер проверяет права и ревизию,
возвращая 304 для неизменившегося списка. При изменении разметки строк нужно поднять
версию `user-table-v1` в сервисе. URL запроса включает `table_owner` для разделения
кэша аккаунтов; сервер проверяет соответствие владельцу сессии.

`ui.js::initCharCounters` поддерживает `data-counter-mode="limit"`: счётчик скрыт,
подсказка появляется только при достижении maxlength. Этот режим применяет
`ProfileForm`; остальные формы сохраняют существующий режим счётчика.

`forms.js::initProfileCompletion` обновляет шкалу `[data-profile-progress]` при вводе
в `[data-profile-form]`; каждое поле помечено `data-profile-completion-field`.
Группа чекбоксов считается одним полем. Серверный состав и начальное значение —
в `services/profile_completion.py`, поведения в инлайновых скриптах нет.
`calendar.js` поддерживает `data-dp-keep-empty`: пустая дата не заполняется
автоматически, доступна очистка; остальные календари сохраняют прежнее поведение.

- **Новое поведение по data-атрибуту** → в подходящий тематический файл, оформи как
  `initXxx(root)` и добавь самовызов `initXxx(document)` в конце файла (и/или имя в
  список `initPageContent` в `modal.js`, если нужно переинициализировать после AJAX).
- **Не создавай инлайновый `<script>` с бизнес-поведением** в шаблоне страницы —
  общее поведение живёт здесь и навешивается по `data-*` (agent-workflow §4).
- **Новый серверный URL для JS** → в `window.VC_URLS` (base.html), читай из него.
