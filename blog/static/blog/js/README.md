# `static/blog/js/` — клиентский JS платформы

Раньше почти весь фронтенд-JS жил инлайном в `base.html` (~2430 строк в одном
`<script>`). Он вынесен сюда и разбит по темам (Фаза 4 рефакторинга). `base.html`
теперь — каркас разметки + маленький конфиг `window.VC_URLS` + подключения этих файлов.

## Как это работает

- Файлы грузятся **обычными `<script src>`** (не ES-модули), поэтому все функции
  остаются в **глобальном scope** — как и было в едином `<script>`. `initPageContent`
  и soft-navigation зовут их через `window[fnName]`.
- **Порядок подключения важен** (задан в `base.html`): модуль может вызывать функции
  предыдущих. В конце каждого модуля — самовызовы `initXxx(document)`, инициализирующие
  текущую страницу; поэтому функция должна быть определена в том же или раньше
  загруженном файле.
- Статические `.js` **не рендерят Django-теги**. Серверные URL приходят через
  `window.VC_URLS` (инлайн-конфиг в `base.html` с `{% url %}`). Нужен новый URL в JS —
  добавь его в `VC_URLS`, а не в `.js`.

## Что в каком файле

`qr-scanner.js` — `initQrScanner(root)` для `[data-qr-scanner]`: камера, фото,
существующая модалка участника, POST сканирования/входа/выхода и освобождение камеры.
В карточке вход/выход/обед и значок — чекбоксы. Новые выборы можно снять до закрытия:
`qrCommit` атомарно сохраняет пакет с серверным временем сканирования. Общий
`closeModal` отправляет отменяемое `modal:before-close`; QR ждёт сохранения, после
успеха закрывает окно принудительно, при ошибке оставляет выбор. `modal:closed`
очищает черновик. Уже сохранённые отметки заблокированы.
Переход в профиль сохраняет контекст и выбор в sessionStorage по оператору; Back
восстанавливает окно, BFCache не заменяет живую карточку параллельным запросом.
Закрытие ждёт окончания обновления/восстановления, чтобы ответ не потерял отметки.
`[data-qr-enroll]` записывает на смену и предлагает вход в том же черновике, сохраняя
другие выборы. При ошибке восстанавливаются исходные блокировки полей.
Декодер `vendor/jsQR.js` 1.4.0 загружается лениво, только при использовании сканера;
изображения камеры/файла обрабатываются локально. URL берутся из `window.VC_URLS`.

## Как добавлять

`ui.js::initCharCounters` поддерживает `data-counter-mode="limit"`: счётчик скрыт,
подсказка появляется только при достижении maxlength. Этот режим применяет
`ProfileForm`; остальные формы сохраняют существующий режим счётчика.

`forms.js::initProfileCompletion` обновляет шкалу `[data-profile-progress]` при вводе
в `[data-profile-form]`; каждое поле помечено `data-profile-completion-field`.
Группа чекбоксов считается одним полем. Серверный состав и начальное значение —
в `services/profile_completion.py`, поведения в инлайновых скриптах нет.
`calendar.js` поддерживает `data-dp-keep-empty`: пустая дата не заполняется
автоматически, доступна очистка; остальные календари сохраняют прежнее поведение.

- **Новое поведение по data-атрибуту** → в подходящий тематический файл, оформи как
  `initXxx(root)` и добавь самовызов `initXxx(document)` в конце файла (и/или имя в
  список `initPageContent` в `modal.js`, если нужно переинициализировать после AJAX).
- **Не создавай инлайновый `<script>` с бизнес-поведением** в шаблоне страницы —
  общее поведение живёт здесь и навешивается по `data-*` (agent-workflow §4).
- **Новый серверный URL для JS** → в `window.VC_URLS` (base.html), читай из него.
