# Оформления интерфейса

## Продолжение: окно настроек и поставка графики (4 ноября 2026)

План до изменений: заменить большую страницу выбора компактной кнопкой справа
в настройках; открыть выбор в существующей модалке; сохранять каждое переключение
сразу, без подтверждения. Цветовая тема применяется без перезагрузки; при смене
оформления оболочка обновляется с повторным открытием окна. Ошибка записи возвращает
прежний выбор. Административные настройки сохраняют свой доступ.

Источник графики: `brandbook_minecraft/minecraft_assets`. Подключить фоны, баннеры,
прозрачный передний план, отдельный свет и мох. Рамы: шесть атласов 768×768,
`border-image-slice:128`, `border-image-repeat:repeat`; готовые квадратные рамки
и raster-preview не растягивать. В статике хранить рабочие ассеты, исходную поставку
не менять. Проверить узкие, широкие и высокие панели, обе темы, модалку, мгновенное
сохранение и ошибку сети. Затем обновить документацию и прогнать проверки проекта.

План до реализации, 4 ноября 2026. Основа: `brandbook_minecraft/brandbook.md`,
`materials.css`, `layouts.css` и HTML-примеры; правила проекта — `CLAUDE.md`,
`coding-principles.md`, `agent-workflow.md`.

## Цель и устройство

Сохранить Nexus по умолчанию. Добавить вручную выбираемое оформление Minecraft
с независимым выбором светлой, тёмной или системной темы. Настройки принадлежат
аккаунту, хранятся в БД и действуют на всех устройствах. Гости остаются в Nexus.
Старый браузерный выбор темы можно учитывать только для гостя: он не должен
переопределять предпочтения другого пользователя на общем устройстве.

Реестр оформлений содержит стабильный идентификатор, название, описание и путь CSS.
Общий шаблон подключает только CSS выбранного оформления поверх базовых компонентов.
Сервер задаёт `data-appearance` и `data-theme` до первого отображения. Поведение
выбора темы находится во внешнем JS, предпочтения сохраняются через защищённый POST.
Выбор открывается в общей модалке и сохраняется по change без отдельного подтверждения.
Автосохранение требует JS. Новые оформления добавляются в реестр,
собственным CSS и при необходимости декоративным partial; доменные страницы не клонируются.

Доступ: личное оформление доступно любому вошедшему пользователю из настроек;
менеджерские панели сохраняют свои проверки прав. Вьюха → сервис → контроллер БД.
В запросе нельзя выбирать владельца настроек — используется только request.user.

## Визуальная реализация

Переиспользовать живые карточки, таблицы, формы, модальные окна, календари и мобильное
меню. Minecraft задаёт деревянную навигацию, слоистое бумажное полотно, сколотые
известняковые, каменные и деревянные рамы; ночью — обсидиан и локальный тёплый свет.
Текст и действия остаются в спокойной внутренней области. Декор не принимает клики,
не перекрывает данные; мобильная версия сохраняет фактуру и глубину без крупных объектов.

Исходные PNG-референсы содержат нарисованный интерфейс; их фрагменты не переносим.
Отдельная графика из `brandbook_minecraft/minecraft_assets` подключена в статике:
окружения, баннеры, передний план, локальный свет и мох. Карточки используют
составные атласы рам; список файлов и назначений — в `minecraft-assets.md`.

## Обзор проекта

Django 5.2, серверные шаблоны, сессионный вход, aiogram как отдельный клиент БД.
`blog/models.py` — модели; `blog/views/` — тонкие доменные вьюхи;
`blog/services/` — правила и ACL; `data_base/data_controller/` — операции БД.
`base.html` и `nexus.css` — единая оболочка, `static/blog/js/` — общие поведения.
Иерархия EventGroup → Event (позиция) → EventShift; её и бизнес-операции оформление
не меняет. Папка `fest_platform` исключена из работы по правилам проекта.

## Реализованный контракт

- `blog/appearance.py`: неизменяемый реестр `APPEARANCES`, безопасный fallback Nexus.
- `User.appearance` / `User.color_theme`: поля миграции `0048`; значения по умолчанию
  `nexus` / `system`. Цветовая тема независима от оформления.
- `GET /settings/`: у менеджера административный хаб, у волонтёра личные настройки;
  в обоих случаях справа компактная кнопка с палитрой. Менеджерские вкладки остаются
  за `manager_required`.
- `GET /settings/?tab=appearance` с AJAX-заголовком отдаёт только общий partial
  `_appearance_controls.html` в `loadModal`. Прямой переход перенаправляется на
  `/settings/?appearance=open`, чтобы открыть ту же модалку после загрузки.
- `POST /settings/appearance/`: только собственный аккаунт, CSRF, валидация всего
  запроса до единственной записи. Принимает оба поля или одно поле темы для кнопок
  оболочки или одно поле оформления. AJAX получает JSON; обычный POST — redirect
  на `/settings/?appearance=open`. Ошибка — HTTP 400.
- `blog/services/appearance.py` → `data_controller.save_user_appearance`: правила,
  запись только переданных полей и аудит `vc.db`.
- Контекстный процессор задаёт атрибуты HTML и подключает CSS/декор из реестра.
  `appearance-bootstrap.js` разрешает системную тему до CSS; `appearance.js`
  сохраняет каждое изменение радиокнопок/быстрых переключателей и откатывает
  визуальное состояние при ошибке. Кнопки подтверждения нет. Цветовая тема меняется
  сразу, без перезагрузки. Смена оформления обновляет всю оболочку и повторно
  открывает модалку через одноразовый URL-параметр, без браузерного хранилища.
  Настройки аккаунта не используют localStorage. Прежний ключ `theme` читается
  только для гостей. Системная тема отслеживает изменение настроек устройства.
- `minecraft.css` ограничен выбранным оформлением; карточки, таблицы, формы,
  календари и модальные окна сохраняют общий DOM и поведение. Главная дополнена
  приветственным блоком; навигация использует единый SVG-набор.
- Необязательные изображения обнаруживаются через staticfiles finders при первом
  показе Minecraft. Для обеих тем готовятся независимые слоты, поэтому быстрый
  переключатель меняет и графику. Отсутствующий файл не порождает запрос 404.
  Кэш наличия графики сбрасывается при перезапуске процесса. Атласы рам и свет
  входят в обязательную статику этой версии.

## Материалы и размеры рам

Каждый `.card`/`.stat-tile` имеет рамку в `::before` и спокойную внутреннюю поверхность
в `::after`. Внешняя рамка: `border-image-slice:128`, `border-image-width:1`,
`border-image-repeat:repeat`. Фиксированная толщина задаётся `--rim-pad`; длинные
стороны набираются повторением. Готовые квадратные `*-frame.png` и `preview-*`
не используются в UI, отдельные углы/кромки уже собраны в `9slice.png`.

Известняк — обычные светлые панели; каменная кладка — статистика; замшелая кладка —
первый показатель; дерево — отдельные панели профиля; обсидиан — ночные карточки;
угольный камень — ночная статистика. Для явного выбора на общей карточке доступен
`data-mc-material="limestone|masonry|timber|obsidian|mossy|ember"`.
На мобильном уменьшается толщина рамки, сохраняется повторение и отдельные углы.

## Добавление следующего оформления

1. Добавить `Appearance(key, title, description, stylesheet, decoration)` в реестр.
   `key` — постоянный slug; CSS и partial — доверенные пути из исходного кода.
2. Написать CSS с селектором `:root[data-appearance="новый-slug"]`, используя общие
   семантические переменные Nexus и обе темы `data-theme="light|dark"`.
3. При необходимости добавить декоративный partial с `aria-hidden`,
   `pointer-events:none` и безопасной областью для данных. Для обычных страниц
   новый комплект шаблонов не требуется.
4. Сгенерировать миграцию choices, выполнить migrate и collectstatic. Проверить
   сохранение выбора, возврат к Nexus, светлую/тёмную темы и мобильную версию.
5. Новая карточка выбора появится из реестра. Для узнаваемой миниатюры дополнить
   `appearance-settings.css` классом `.appearance-preview--новый-slug`.
