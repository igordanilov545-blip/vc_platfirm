## Пользователи и Роли

### `users` — Пользователи (Volunteers)

Центральная сущность системы. Наследуется от `AbstractBaseUser`. Вход осуществляется через Telegram ID.

| Поле | Тип | Описание | Источник данных |
|------|-----|----------|-----------------|
| `id` | INT PK | Уникальный идентификатор | Автоинкремент БД |
| `system_username` | VARCHAR(50) | Системный логин | Генерируется системой |
| `telegram_id` | VARCHAR(50) | Числовой ID Telegram (уникальный) | Telegram Bot API при первом входе |
| `telegram_username` | VARCHAR(100) | Никнейм в Telegram (@name) | Telegram Bot API при взаимодействии |
| `VK_username` | VARCHAR(100) | VK для связи | Ввод пользователем в профиле |
| `first_name` | VARCHAR(100) | Имя | Telegram API / Форма профиля |
| `last_name` | VARCHAR(100) | Фамилия | Telegram API / Форма профиля |
| `email` | VARCHAR | Электронная почта | Ввод пользователя |
| `phone` | VARCHAR(20) | Номер телефона | Ввод пользователя |
| `birthday` | DATE | Дата рождения | Ввод пользователя |
| `about` | TEXT | Информация о себе | Ввод пользователя |
| `gender` | BOOLEAN | Пол | Ввод пользователя |
| `status` | VARCHAR(20) | Статус: `active`, `inactive`, `blacklisted` | Установка менеджером |
| `comment` | TEXT | Внутренний комментарий менеджера | Ввод менеджером |
| `created_at` | TIMESTAMP | Дата регистрации | Автоматически |
| `last_event_at` | TIMESTAMP | Дата последнего участия | Обновляется системой после меро |
| `total_event_count` | INT | Мероприятий за все время | Агрегат `COUNT(participations)` |
| `season_event_count` | INT | Мероприятий за текущий сезон | Агрегат с фильтром по сезону |
| `total_hours` | INT | Часов за все время | Агрегат `SUM(participations.hours)` |
| `season_hours` | INT | Часов за текущий сезон | Агрегат с фильтром по сезону |

### `managers` — Менеджеры

История выдачи и отзыва ролей менеджеров.

| Поле | Тип | Описание | Источник данных |
|------|-----|----------|-----------------|

| `assigned_by` | FK → users | Кто назначил роль | ID текущего менеджера |
| `total_events` | INT | Мероприятий курировал за все время | Агрегат по событиям в роли manager |
| `season_events` | INT | Мероприятий за сезон | Агрегат с фильтром по сезону |

## Бизнес-правила и логика

1.  **Кэширование статистики:** Поля `total_hours`, `season_hours`, `total_event_count`, `season_event_count` в таблице `users` являются агрегированными. Они пересчитываются при изменении статуса в `participations`.
2.  **Историчность ролей:** Активной ролью считается запись в `managers` или `team_leaders`, где `revoked_at IS NULL`.
3.  **Обработка заявок:**
    *   Менеджер принимает (`approved`) или отклоняет (`rejected`) заявку.
    *   Отклоненные заявки переводят человека в "резерв".
    *   При дубликатах от одного пользователя менеджеру показывается только последняя заявка.
4.  **Требования:** Таблица `user_requirement_exceptions` работает по принципу "белого списка исключений". Если записи нет, считается, что волонтер соответствует требованию.
5.  **People Helped:** Поле `people_helped` в `events` должно быть обязательным для заполнения при закрытии смены/мероприятия.
6.  **Аутентификация:** Вход только по `telegram_id`. Пароль не используется (`set_unusable_password`).
