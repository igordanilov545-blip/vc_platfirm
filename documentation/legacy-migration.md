# Миграция старых баз и ФиП

> Статус: **реализовано** (2026-11-11, ветка `agent/opus/legacy-migration`).
> Черновик с вопросами согласован с пользователем; ответы зафиксированы в §8.
> Код: `blog/services/legacy_migration.py` (этапы), `profile_conflicts.py` (анкеты),
> `position_pool.py` (пул функций), `fap_workbook.py` (ФиП); CRUD —
> `data_controller/legacy_migration.py`; экраны — `blog/views/legacy_migration.py`.

## 1. Что было сломано

Прежняя «Загрузка базы» за один проход угадывала структуру по тексту ячейки:
позиция = первые цифры (`7.2`), поэтому в одну «позицию» сливались тим-лидер зоны,
ассистенты 42,2 км и 10 км; название мероприятия — кусок заголовка; смены — с
временем 00:00 и 0 часов; одна база, один проход. Реальный ФиП ММ 2026 к тому же
не читался: лишняя колонка «Наставник» сдвигала дни.

## 2. Как устроены файлы

**База** (лист «База»): колонки анкеты, затем колонки «мероприятие + день». Ячейка —
`<код> - <строка ФиП>`, например `7.2 - Ассистент выдачи номеров… — 42,2 км`.
Код = `<номер функции>.<номер набора тим-лидера внутри функции>`; при одном наборе —
просто номер (`5 - Ашер в городе`). Встречаются значения без кода, опечатки, мусор.

**ФиП** (только лист «Смены», остальные игнорируются): функция → блоки до
«ИТОГО В ЗОНЕ» → строки позиций; колонка тим-лидеров, менеджеры БС, время/check-in/
количество по дням. Нумерация наборов тим-лидеров совпадает с кодами базы
(10.1 ПО1 … 10.11 ПП5, 7.1 справки … 7.5 футболки).

## 3. Модель

- **Позиция платформы = набор одного тим-лидера внутри блока «ИТОГО В ЗОНЕ».**
  Тим-лидеры видят свои наборы, менеджер — разрез «по точкам» (не «дистанция
  500/700», а по каждому пункту и его тим-лидеру). Один человек может быть
  тим-лидером или волонтёром нескольких позиций.
- **Функции переиспользуемы** — таблица `event_categories` стала пулом функций
  («Дистанция», «Штаб и сервисы для волонтёров», «Выдача стартовых пакетов»,
  «Проверка медицинских справок», «Финиш», «Старт»…), к функции в пуле привязаны
  типовые позиции (`position_templates`). Форма позиции подсказывает название из
  пула; ФиП и миграция назначают позиции функцию по ключевым словам. Пул
  редактируется в «Настройки → Функции и позиции». Локации и прочие привязки
  позиций остались прежними.
- Схема таблиц — [db.md](db.md), раздел «Миграция старых баз и пул функций».

## 3в. Смены функции: матрица «смена × роль» (2026-11-11, решение пользователя)

- Внутри функции создаются **смены** (`FunctionShift`: дата, время, сколько людей
  нужно всего). Позиция = **роль** человека в смене; клетка матрицы — `EventShift`
  позиции-роли с `function_shift` и своим «нужно».
- «+ Смена» сразу заводит роли «Тим-лидер зоны X» (1) и «Волонтёр зоны X» (нужно − 1);
  X — поле «Зона» (по умолчанию название функции). Роли берутся из пула функции или
  попадают туда один раз; существующая роль мероприятия переиспользуется.
- В смене можно менять число на каждую роль; под ролями — «Назначено по ролям N из M»,
  при расхождении — ⚠ с подсказкой (и в форме, и в матрице на странице мероприятия).
- «+ Роль» — подсказки только из пула этой функции.
- **Ссылка Добро.ру — у мероприятия** (`EventGroup.dobro_ru_link`), копируется во все
  его позиции. Из формы позиции убраны масштаб, организация, контактное лицо, пост в
  канале и Добро.ру (поля модели остаются).

## 3б. Мероприятие → функции → позиции (2026-11-11, решение пользователя)

Отменяет «позиция = набор тим-лидера» из §3 и §8.
- **Функция** — блок колонки B ФиП («Организация сервисов для отдельных клиентских
  групп», «Волонтёры-атташе и волонтёры отеля-партнёра», «Волонтёры режиссёрской
  группы»…). Пул функций = названия из ФиП (13, `position_pool.DEFAULT_FUNCTIONS`),
  можно добавлять свои. Прежние выдуманные названия пула перенесены миграцией 0051.
- **Позиция** — строка «Позиция» ФиП со своим количеством и временем по дням
  («Волонтёр VIP-финиша», «Тим-лидер волонтёров …»). Одинаковые строки разных зон
  различаются кодом набора («Хостес · 7.5»). Функция позиции — связь
  `event_category_map`.
- **Тим-лидер** — тоже позиция функции; он получает роль тим-лидера и назначение на
  **все позиции своей функции** в мероприятии — видит весь набор по каждой смене.
  Откат колонки снимает и эти назначения (сделанные загрузкой).
- **Сопоставление**: для значения базы выбирается функция (сначала функции
  мероприятия, затем пул, «＋ Новая функция»), затем позиция — список сужается по
  функции; новая позиция создаётся внутри выбранной функции.
- Мероприятия, импортированные до этого решения (позиция = зона), остаются в старом
  формате; чтобы перевести их, откатите колонки и привяжите ФиП заново к новому
  мероприятию.

### Ручное создание мероприятия

На странице мероприятия — блок «Функции мероприятия»: «+ Функция» (из пула или
новая, она попадает в пул), у каждой функции — «+ Позиция». В форме позиции поле
«Функция» стоит первым (функции мероприятия, затем пул, «＋ Новая функция») и
обязательно для новой позиции; подсказки названия — позиции выбранной функции из
пула, а введённое название само запоминается в пуле. В таблице позиций — колонка
«Функция». Сервис — `blog/services/event_functions.py`; список функций мероприятия
хранится в `event_directions` (те же записи создаёт ФиП).

## 3а. Доработки 2026-11-11 (второй заход)

- **Фоновые загрузки.** «Загрузить людей» и загрузка колонок идут задачей
  (`MigrationJob`, `blog/services/migration_jobs.py`): отдельный поток веб-процесса,
  порции в коротких транзакциях, прогресс в БД. Вверху каждой страницы менеджера —
  строка «Идёт загрузка … N%» с полосой и кнопкой «Отменить загрузку» → встроенное
  подтверждение «Да, отменить». Отмена удаляет созданное этой загрузкой (аккаунты,
  связи строк, расхождения/заметки; для колонок — как «Откатить»). Дополненные
  пустые поля уже существовавших профилей не откатываются. Одновременно идёт одна
  загрузка. Если процесс перезапустился, задача через 3 минуты без обновлений
  показывается «прервана» — запуск заново продолжает с места остановки.
- **Библиотека ФиП.** В хабе и на странице базы можно выбрать сразу несколько
  файлов: каждый проверяется отдельно (ошибка одного не мешает остальным), повтор
  того же файла не дублируется. Файл получает название по имени («Ночной 2026»).
- **Колонки базы ↔ ФиП.** На странице базы — таблица: для каждой колонки выбирается
  «ФиП · день». Мероприятие создаётся по названию ФиП (или берётся то, к которому ФиП
  уже привязан), ФиП применяется один раз, дата колонки = день ФиП. ✨-подсказка —
  единственный ФиП с днём, совпадающим с датой колонки. Колонкам без ФиП дата
  вводится тут же.
- **Разбор реальных ФиП.** Дата дня берётся из блока количества («Pre-race 1» в
  заголовке дня — не ошибка); расхождение только в годе — предупреждение; несколько
  блоков количества на один день («20 июня 1/2 смена») суммируются; год, которого нет
  в файле, берётся из имени файла или года базы. Время работы зоны по-прежнему **не**
  заменяет check-in/out (правило db.md) — см. открытый вопрос в §8.
- **Загрузка в хабе.** Формы «Загрузить базу» и «Загрузить файлы ФиП» стоят внутри
  карточек «Базы» и «Библиотека ФиП». Тип файла определяется по листам («База» →
  база, «Смены» → ФиП), поэтому файл попадает куда нужно, в какую бы форму его ни
  отправили. Год базы при загрузке необязателен: имя файла → самый частый год в
  датах заголовков колонок → текущий год. Предел размера файла — константа
  `legacy_upload_max_mb` (по умолчанию 50 МБ: в ФиП много вкладок, читается одна).
  Ошибки формы — сообщением вверху страницы и в `vc.web`.
- **Смены миграции не мешают обновлять ФиП.** Смены «время не указано», созданные
  загрузкой колонок (`legacy_import_shifts`), — архивная явка, а не план: в обмен с
  ФиП они не входят, поэтому новая версия ФиП после загрузки колонок не отклоняется
  как «Конфликт». Тот же файл повторно не создаёт версию-дубль. ФиП, загруженные до
  библиотеки, разбираются из сохранённого файла при первом обращении.
- **Подсказки состояний.** У каждого состояния колонки — всплывающее пояснение
  «что не так и что сделать»; у «не сопоставлены значения» перечислены сами
  значения и ссылка «показать» (фильтр «Только несопоставленные»), несопоставленные
  строки — сверху и отмечены полосой.
- **Таблицы** помещаются в карточку (текст переносится), поле «Новая позиция»
  появляется под выбором позиции только при «＋ Новая позиция»; ввод в нём сам
  выбирает этот вариант. Даты — компактный календарь (`data-dp-popup`): поле
  ДД.ММ.ГГГГ, календарь выпадает при фокусе.
- **Пул позиций** пополнен типовыми позициями из 5 реальных ФиП; позиции из
  применённых ФиП и новые позиции миграции запоминаются в пуле. Таблица
  «позиция → функция по ключевому слову» — [position-pool.md](position-pool.md).

## 4. Этапы («Настройки → Миграция старой базы»)

Хаб показывает базы по годам, мероприятия из баз, версии ФиП и **какие колонки ещё
не загружены и почему** (не привязана к мероприятию, нет даты, не сопоставлены
значения, люди не загружены, сопоставление изменено, пропущена, пустая).

1. **База → люди.** Файл и год (одна база = один год). «Загрузить людей» создаёт
   анкеты и комментарии координатора/ТЛ. Один человек из разных баз — один аккаунт
   (отпечатки Telegram → телефон → почта). Пустое ФИО — строка пропускается, одно
   пустое — `unnamed`; нераспознанный текст контактов сохраняется, но не матчится.
2. **Колонки → мероприятие.** Отметить колонки (chip-select), задать название
   (пусто — как в таблице) или добавить к существующему мероприятию. Колонку без
   ненужных данных можно «пропустить» — она не считается забытой.
3. **ФиП.** Загрузить версию — все версии хранятся. Позиции и смены создаёт обычный
   импорт ФиП; архивный файл без служебных ID сопоставляется с прежней версией по
   названию набора. Без ФиП позиции создаются из значений.
4. **Сопоставление.** Одна таблица уникальных значений на все колонки мероприятия с
   числом людей по дням. Для значения: позиция / «новая позиция» (название с
   подсказкой из пула) / «пропустить» и роль. ✨-подсказка: точный код ФиП сильнее
   всего, затем похожий текст строк ФиП; значение без кода подсказывается только при
   почти дословном совпадении. Роль «тим-лидер» — если в тексте есть «тим-лидер»
   (регистр, пробел/дефис/слитно, ё/е не важны); «Помощник тим-лидера» — волонтёр.
5. **Загрузка.** По колонке или «все готовые». Колонка готова, когда у неё есть дата
   и все значения сопоставлены/пропущены. Смена — по дате колонки (несколько колонок
   одного дня — по порядку; нет смены ФиП — смена «время не указано»). Создаются
   одобренная заявка, решение по смене, участие «Был» с часами из смены ФиП;
   тим-лидер получает `EventStaff` на позиции и глобальную роль тим-лидера. Агрегаты
   пересчитываются. Повтор — без дублей.
6. **Дозагрузка и обновление.** Новая колонка/база/версия ФиП проходит те же шаги.
   Изменённое сопоставление уже загруженной колонки помечает её «перезагрузите»:
   участия переносятся. Участия, которые сотрудник изменил (статус, ручные часы),
   не переносятся и не откатываются — показываются как конфликт. «Откатить» удаляет
   только созданное этой колонкой.

## 5. Пересечение баз и анкеты

В профиле — только самые актуальные данные:
- пустое поле дополняется из базы;
- профиль, созданный базами: более новая база (год) обновляет данные, более
  старая — нет;
- профиль, который человек ведёт сам (настоящий Telegram или веб-логин), молча не
  меняется: создаётся расхождение, при входе — баннер «Уточнить данные», на
  странице `/profile/actualize/` человек выбирает своё / из базы / вводит новое
  (с проверкой формата).

Каждое изменение и расхождение записывается в комментарий «Изменения данных по
старым базам», видимый только сотрудникам.

## 6. Даты и разбор

Дата колонки — только явная: «24.09», «24.09.2026» или «24 сентября» (год — год
базы). Иначе дату указывает человек; загрузка колонки до этого невозможна.
«(резерв)» — реальные участники без определённого дня: им дата тоже ставится
вручную. Глубокий разбор текста ячеек не делается.

## 7. Проверено на реальных файлах (копия БД)

База ММ 2026: 3405 строк, 75 без ФИО пропущено, 3349 аккаунтов; ФиП ММ — 39
позиций; 89 уникальных значений ММ; все значения с кодом получили верную
подсказку. Загрузка всех колонок ММ: 2311 участий (2211 с часами из ФиП),
83 тим-лидера, ~130 с (большая часть — пересчёт агрегатов и достижений);
повтор — 7 с, без новых записей.
