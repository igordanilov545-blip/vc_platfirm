# Шаблоны отчётов за период (Excel · PDF · Комплексный)

> Документ детально описывает **все выгружаемые отчёты** за период: макет, состав, порядок
> разделов/колонок и пример каждого файла. Значения внутри примеров записаны как
> `{как считается}` — формула/источник берётся из [reports.md](reports.md) §7.
>
> Доступно только менеджерам. Период выбирается пресетом (неделя / месяц / сезон) или
> вручную через календарь (дата начала — дата конца). Одна и та же выборка периода
> используется всеми тремя форматами.
>
> Форматы:
> - **PDF-отчёт за период** — оформленный человекочитаемый документ (§1).
> - **Excel-отчёт за период** — машиночитаемая многолистовая выгрузка (§2).
> - **Комплексный отчёт за период** — PDF + Excel одним пакетом (§3).

---

## Общие соглашения

- **Период** — `[date_from … date_to]`. Для пресета сезон границы берутся из `seasons`.
- **Предыдущий период** — аналогичный по длине интервал непосредственно перед текущим
  (для блока «Сравнение»).
- `{…}` в примерах — плейсхолдер: показывает, **как** считается значение, а не конкретное число.
  Реальный экспорт подставляет вычисленные значения.
- Источник каждой метрики — соответствующая строка таблиц в [reports.md](reports.md) §7.
- Пустые/неопределённые значения выводятся как `—`.

## 1. PDF-отчёт за период

Оформленный документ с брендированием ВЦ. Структура — сверху вниз, по одному блоку на раздел,
графики встроены как изображения.

## 2. Excel-отчёт за период

Многолистовая книга `.xlsx`. Один лист = один блок. Первая строка каждого листа — заголовок
периода, вторая — шапка колонок, дальше данные. Значения — вычисленные (в шаблоне ниже
показаны как `{как считается}`).

### Лист «Обзор»

| Показатель | Значение |
|------------|----------|
| Период | `{date_from} — {date_to}` |
| Всего часов | `{SUM(participations.hours) WHERE attended, период}` |
| Всего мероприятий | `{COUNT(DISTINCT events) через event_days, период}` |
| Уникальных волонтёров | `{COUNT(DISTINCT participations.user_id)}` |
| Закрытых смен | `{COUNT(participations) WHERE attended}` |
| Новых волонтёров | `{COUNT(users) WHERE created_at в периоде}` |
| Людей получили помощь | `{SUM(events.people_helped) по меро периода}` |

### Лист «Топы»

| Тип | Позиция | Имя / категория | Значение |
|-----|---------|-----------------|----------|
| Волонтёр | `{1..10}` | `{nickname}` | `{SUM(hours) GROUP BY user_id ORDER BY DESC}` |
| Категория | `{n}` | `{event_categories.name}` | `{COUNT(participations) GROUP BY category}` |

### Лист «Воронка»

| Этап | Значение |
|------|----------|
| Подано заявок | `{COUNT(applications), created_at в периоде}` |
| Одобрено | `{COUNT WHERE status='approved', обработано в период}` |
| Отклонено (резерв) | `{COUNT WHERE status='rejected'}` |
| Явка | `{COUNT(participations) WHERE attended}` |
| Неявка без предупреждения | `{COUNT WHERE absent_unexcused}` |
| Конверсия подал → явка, % | `{attended / total_applications × 100}` |

### Лист «Эффективность набора»

| Мероприятие | Нужно волонтёров | Явка | % закрытия слотов | Ср. время набора |
|-------------|------------------|------|-------------------|-------------------|
| `{events.title}` | `{SUM(event_days.volunteer_needed)}` | `{SUM attended}` | `{attended / needed × 100}` | `{AVG(последний approved → дата меро)}` |

### Лист «Нагрузка персонала»

| Роль | ФИО | Меро за период | Заявок обработано | Ср. время обработки |
|------|-----|----------------|-------------------|----------------------|
| Менеджер | `{ФИО}` | `{COUNT event_staff manager}` | `{COUNT applications assigned_by}` | `{AVG(assigned_at − created_at)}` |
| Тим-лидер | `{ФИО}` | `{COUNT event_staff team_lead}` | `—` | `—` |

### Лист «Retention / Churn»

| Показатель | Значение |
|------------|----------|
| % возврата волонтёров | `{вернувшиеся / активные прошлого периода × 100}` |
| Churn rate, % | `{доля users с churn_score ≥ const.churn_blacklist_threshold}` |
| Новых в blacklist | `{COUNT(users) blacklisted за период}` |

### Лист «Проблемные зоны»

| Категория проблемы | Мероприятие / волонтёр | Метрика |
|--------------------|------------------------|---------|
| Низкий рейтинг | `{events WHERE AVG(rating) < 6}` | `{AVG(rating), кол-во отзывов}` |
| Высокий % отказов | `{events WHERE rejected/total > 0.5}` | `{% отказов}` |
| Недобор | `{events WHERE attended/needed < 0.8}` | `{% набора}` |
| На грани blacklist | `{users WHERE churn ≥ threshold×0.8}` | `{текущий churn_score}` |

### Лист «Сравнение»

| Метрика | Текущий период | Прошлый период | Δ абс. | Δ % |
|---------|----------------|----------------|--------|-----|
| Часы | `{текущее}` | `{предыдущее}` | `{тек − пред}` | `{(тек−пред)/пред×100}` |
| Мероприятия | `{…}` | `{…}` | `{…}` | `{…}` |
| Уникальных волонтёров | `{…}` | `{…}` | `{…}` | `{…}` |
| Новых волонтёров | `{…}` | `{…}` | `{…}` | `{…}` |
| Конверсия заявок | `{…}` | `{…}` | `{…}` | `{…}` |

### Лист «Данные для графиков» (сырьё)

| График | Ключ | Значение |
|--------|------|----------|
| Время отклика | `{бакет: <1ч / 1–6ч / 6–24ч / >24ч}` | `{COUNT(applications) по бакету, applications.created_at − events.published_at}` |
| Публикация постов | `{час суток / день недели}` | `{COUNT(events.published_at)}` |
| Динамика активности | `{неделя}` | `{COUNT(participations) по неделе}` |

## 3. Комплексный отчёт за период

Объединённая выгрузка за один и тот же период: оформленный **PDF** (§1) + машиночитаемый
**Excel** (§2) одним пакетом.

Состав пакета:

| Файл | Содержание |
|------|------------|
| `report_{date_from}_{date_to}.pdf` | Полный оформленный отчёт из §1 (все 8 блоков + графики) |
| `report_{date_from}_{date_to}.xlsx` | Все листы из §2 |

> Оба файла строятся на **одной** выборке периода, поэтому цифры в PDF и Excel идентичны.
> PDF — для чтения и передачи руководству/грантодателям; Excel — для дальнейшего анализа.
