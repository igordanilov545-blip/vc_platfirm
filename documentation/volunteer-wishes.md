# Табличка желающих

> Люди, которые **заранее, ещё до старта набора** попросили знакомых тим-лидеров или
> менеджеров взять их на следующий забег. Мероприятия в платформе к этому моменту ещё
> нет — оно только в календаре сообщества. Поэтому запись **не привязана** к
> `EventGroup`: человек с подсказками хранится отдельно, а со страницей мероприятия
> сопоставляется при её показе.

## Кто что может

| Действие | Волонтёр | Тим-лидер | Менеджер |
|---|---|---|---|
| Видеть табличку (сайт, страница мероприятия) | ✗ | ✓ | ✓ |
| Добавить желающих (бот `🙋 Желающие` / `/wish`, сайт) | ✗ | ✓ | ✓ |
| «✓ Забрал» на странице мероприятия | ✗ | ✓ | ✓ |
| Снять отметку «забрал» | ✗ | ✓ только свою | ✓ любую |
| Править / удалить строку | ✗ | ✓ только добавленную им | ✓ любую |
| «Отменить запись» в боте (всё сообщение) | ✗ | ✓ только своё | ✓ только своё |

«Тим-лидер» здесь — активная глобальная роль (`team_leaders.revoked_at IS NULL`), не
назначение на конкретное меро: мероприятия ещё нет. Единая проверка —
`services/volunteer_wishes.py::can_manage_wishes` (веб и бот).

## Данные (`volunteer_wishes`, миграция 0056)

Одна строка = **человек × мероприятие из сообщения**. «Хочет на СКБС и на Скорость» —
две строки: «забрал на СКБС» не должно прятать человека со Скорости. Строки одного
сообщения связаны `batch_id`.

| Поле | Смысл |
|---|---|
| `telegram_username`, `phone`, `full_name` | контакты из сообщения (username без `@`, в нижнем регистре; телефон `+7…`) |
| `user` | найденный аккаунт: telegram → телефон → ФИО (`find_matching_user`, «Фамилия Имя») |
| `event_hint` | название, как его пишут в чате: «Скорость», «СКБС» |
| `wish_dates` | ISO-даты; без года/месяца — ближайшая **не прошедшая** дата |
| `position_hint` | неформальная позиция: «справки», «ПП/дистанцию» |
| `raw_text` | исходное сообщение целиком (разбор эвристический — видно, что писали) |
| `source`, `added_by`, `created_at` | откуда и кто добавил |
| `taken_event_group`, `taken_by`, `taken_at` | «забрал» — в какое мероприятие, кто, когда |

## Разбор сообщения (`parse_wish_message`)

Понимает примеры из чатов: `@username Фамилия Имя хочет на СКБС и на Скорость`,
`@username хочет 14 и 15-го`, `@username хочет 21 ноября на Скорость`,
`@username\nХочет 21-22`, `Хочет на скорость 21 и 22 @username`, а также несколько
`@юзернеймов`/телефонов в одном сообщении (телефон рядом с юзернеймом — тот же человек).

- Даты: `21.11`, `21.11.2026`, `14 и 15-го`, `21-22` (диапазон), `21 ноября`. Числа с
  единицами («10 км», «18 лет») и время («10:00») датами не считаются.
- Фразы после «на» — мероприятие или позиция. Позиция — если слово похоже на
  встроенный список (справки, ПП, дистанция, старт, финиш…) или на название функции,
  категории или типовой позиции из пула платформы.
- Несколько строк: строка с контактом и своим пожеланием — новый человек со своим
  пожеланием; «Хотят на скорость:\n@a\n@b» — одно пожелание на двоих.
- Нет ни `@юзернейма`, ни телефона, ни «Фамилия Имя» перед «хочет» — ничего не
  записывается (`no_people`), бот просит прислать ещё раз.

Ошиблось — строку правят на сайте («✎»), исходный текст виден рядом.

## Сопоставление с мероприятием (`wishes_for_event_group`)

На странице мероприятия (под таблицей функций) ТЛ и менеджер видят карточку
«🙋 Желающие»:

- **есть название** → подходит, если каждое слово подсказки — слово/основа слова
  названия мероприятия («скорость» ↔ «Скорость 2026») или подсказка — аббревиатура
  («СКБС» ↔ «Северный Кросс «Белые Сопки»»). Даты при этом не обязательны;
- **нет названия, есть даты** → хотя бы одна дата совпадает с днём смены мероприятия;
- остальные не забранные — в раскрывашке «Остальные желающие без совпадения», чтобы
  никого не потерять.

«✓ Забрал» ставит отметку с мероприятием страницы; забранный человек показывается
только в этом мероприятии и пропадает из «прочих» у других. «Снять отметку» возвращает
его в общий пул.
