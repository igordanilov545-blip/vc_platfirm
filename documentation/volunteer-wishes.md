# Табличка желающих

> Люди, которые **заранее, ещё до старта набора** попросили знакомых тим-лидеров или
> менеджеров взять их на следующий забег. Мероприятия в платформе к этому моменту ещё
> нет — оно только в календаре сообщества. Поэтому запись **не привязана** к
> `EventGroup`: человек с подсказками хранится отдельно, а со страницей мероприятия
> сопоставляется при её показе.

## Кто что может

| Действие | Волонтёр | Тим-лидер | Менеджер |
|---|---|---|---|
| Видеть табличку (сайт, страница мероприятия) | ✗ | ✓ | ✓ |
| Добавить желающих (бот `🙋 Желающие` / `/wish`, сайт) | ✗ | ✓ | ✓ |
| «✓ Забрали» (без деталей) | ✗ | ✓ | ✓ |
| «В смену…» (заявка сразу одобрена на смену) | ✗ | ✓ только в смены своих позиций | ✓ в любые |
| «↩ Вернуть в желающие» (снять «Забрали») | ✗ | ✓ | ✓ |
| Править / удалить строку («✕» — с подтверждением) | ✗ | ✓ только добавленную им | ✓ любую |
| «Отменить запись» в боте (всё сообщение) | ✗ | ✓ только своё | ✓ только своё |

«Тим-лидер» здесь — активная глобальная роль (`team_leaders.revoked_at IS NULL`), не
назначение на конкретное меро: мероприятия ещё нет. Единая проверка —
`services/volunteer_wishes.py::can_manage_wishes` (веб и бот).

## Данные (`volunteer_wishes`, миграции 0056–0057)

Одна строка = **человек × мероприятие × один день**. «Хочет на СКБС и на Скорость 21 и
22» — четыре строки: «забрал на СКБС» не прячет человека со Скорости, а два его дня
могут забрать **разные тим-лидеры**. Строки одного сообщения связаны `batch_id`.

**Ссылки на реальные записи.** `user` — аккаунт, найденный по Telegram → телефону → ФИО;
`event_group` — мероприятие, если оно найдено **однозначно**: среди непрошедших (последний
день смен не раньше сегодня или смен ещё нет) ровно одно подходит по названию, а без
названия — ровно одно со сменой в этот день. Не найдено или кандидатов несколько — строка
остаётся текстом, в таблице «нет на платформе» / «нет в базе». Мероприятие, созданное или
сохранённое позже (`EventGroupForm.save` → `link_wishes_to_group`), само подхватывает
таких желающих. В «✎» аккаунт выбирается общим выбором людей, мероприятие — списком
непрошедших, день — общим календарём.

**Дублей нет** (`find_duplicate`): тот же человек (тот же аккаунт, @username или телефон;
ФИО — только если других контактов нет) × то же мероприятие (ссылка или название) × тот же
день среди не архивных строк. Повторная запись — в т.ч. другим тим-лидером — новую строку
не создаёт: бот отвечает «♻️ Уже в табличке … — записал(а) X», сайт — «уже были в
табличке: N», а пустые поля строки (позиция, аккаунт, контакты, мероприятие)
дополняются. Правка, превращающая строку в дубль, отклоняется. Проверка — в сервисе, не
ограничением БД: архивные строки не должны мешать записи на следующий забег.

Миграция 0057 разбила старые строки со списком дат на однодневные и слила дубли в самую
раннюю (статус «Забрали» переносится).

| Поле | Смысл |
|---|---|
| `telegram_username`, `phone`, `full_name` | контакты из сообщения (username без `@`, в нижнем регистре; телефон `+7…`) |
| `user` | найденный аккаунт: telegram → телефон → ФИО (`find_matching_user`, «Фамилия Имя») |
| `event_hint` | название, как его пишут в чате: «Скорость», «СКБС» |
| `event_group` | реальное мероприятие (если найдено однозначно), иначе пусто |
| `wish_date` | один день; без года/месяца — ближайшая **не прошедшая** дата; пусто — «ближайший забег» |
| `position_hint` | неформальная позиция: «справки», «ПП/дистанцию» |
| `raw_text` | исходное сообщение целиком (разбор эвристический — видно, что писали) |
| `source`, `added_by`, `created_at` | откуда и кто добавил |
| `taken_at`, `taken_by` | статус «Забрали»: когда и кто (статус = `taken_at` задан) |
| `taken_event_group`, `taken_shift` | куда забрали — необязательно (миграция 0058) |

## Разбор сообщения (`parse_wish_message`)

Понимает примеры из чатов: `@username Фамилия Имя хочет на СКБС и на Скорость`,
`@username хочет 14 и 15-го`, `@username хочет 21 ноября на Скорость`,
`@username\nХочет 21-22`, `Хочет на скорость 21 и 22 @username`, а также несколько
`@юзернеймов`/телефонов в одном сообщении (телефон рядом с юзернеймом — тот же человек).

- Даты: `21.11`, `21.11.2026`, `14 и 15-го`, `21-22` (диапазон), `21 ноября`. Числа с
  единицами («10 км», «18 лет») и время («10:00») датами не считаются.
- Фразы после «на» — мероприятие или позиция. Позиция — если слово похоже на
  встроенный список (справки, ПП, дистанция, старт, финиш…) или на название функции,
  категории или типовой позиции из пула платформы.
- Несколько строк: строка с контактом и своим пожеланием — новый человек со своим
  пожеланием; «Хотят на скорость:\n@a\n@b» — одно пожелание на двоих.
- Нет ни `@юзернейма`, ни телефона, ни «Фамилия Имя» перед «хочет» — ничего не
  записывается (`no_people`), бот просит прислать ещё раз.

Ошиблось — строку правят на сайте («✎»), исходный текст виден рядом.

## Сопоставление с мероприятием (`wishes_for_event_group`)

На странице мероприятия (под таблицей функций) ТЛ и менеджер видят карточку
«🙋 Желающие»:

- **есть ссылка на мероприятие** → показывается только в нём;
- **есть название** → подходит, если каждое слово подсказки — слово/основа слова
  названия мероприятия («скорость» ↔ «Скорость 2026») или подсказка — аббревиатура
  («СКБС» ↔ «Северный Кросс «Белые Сопки»»). Даты при этом не обязательны;
- **нет названия, есть день** → день совпадает с днём смены мероприятия;
- остальные не забранные — в раскрывашке «Остальные желающие без совпадения», чтобы
  никого не потерять.

**Забрать** можно на любой строке — в общей табличке и на странице мероприятия — двумя путями:

- **«✓ Забрали»** в один клик, без деталей: тим-лидер уже сам написал человеку и перенёс
  его к себе. Мероприятие подставляется со страницы, где нажали, или из ссылки строки;
  может остаться пустым (`mark_wish_taken`).
- **«В смену…»** — общая модалка: выбрать смену (тим-лидер видит только смены своих
  позиций, менеджер — все; смена в день строки выбрана заранее) и, по желанию, роль из
  плана смены. Человек сразу получает одобренную заявку на эту смену и появляется в её
  таблице явки — тот же путь, что ручная заявка + решение по смене
  (`take_wish_into_shift` → `create_manual_application` → `process_shift_decision`).
  Нет аккаунта — создаётся служебный по ФИО, как «＋ волонтёр»; нет и ФИО — просим
  привязать аккаунт через «✎».

Человек со статусом «Забрали» не исчезает сразу. Он остаётся в табличке со статусом, кто и когда забрал, и датой «в табличке до…»:
в своём мероприятии и в других подходящих по названию/датам (с пометкой «в «X»», без
кнопки «Забрал», чтобы не забрать дважды); в «прочих» других мероприятий его нет.

Из таблички строка уходит в **архив** (страница `/wishes/`, вкладка «Архив забранных»),
когда наступает раньшее из двух:

- мероприятие, куда забрали, прошло (последний день смен раньше сегодня);
- статус «Забрали» висит дольше `wish_taken_hide_days` дней (Const, по умолчанию 3).

Запись при этом не удаляется. «↩ Вернуть в желающие» (любой ТЛ/менеджер, и из архива
тоже) снимает статус — человек снова в общем пуле. Заявка, созданная через «В смену…»,
при этом остаётся: её отклоняют в таблице смены, как любую другую.

**«Скрыть забранных»** — кнопка-переключатель в карточке мероприятия
(`?wishes_hide_taken=1`) и на странице `/wishes/` (`?hide_taken=1`): показывает только
тех, кого ещё никто не забрал. Вкладки `/wishes/`: «Желающие» (по умолчанию), «Мои»,
«Архив забранных».
